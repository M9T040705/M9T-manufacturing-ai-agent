# 工业AI项目落地实施手册

> 本文档是从MVP到真实生产的执行指南。每个项目包含：数据接入清单、WBS步骤、验收指标、人审边界、常见坑。

---

## 通用技术底座说明

以下5个项目共享同一套技术底座（已在本代码库中实现）：

| 底座模块 | 文件 | 作用 | 真实部署要做什么 |
|---------|------|------|----------------|
| Agent引擎 | `core/agent_engine.py` | 意图识别→任务拆解→取数→分析→交付 | 接LLM做语义意图识别（当前是关键词） |
| 数据连接层 | `core/data_connector.py` | 统一ERP/MES/WMS/QMS取数 | 替换mock方法为真实API/数据库连接 |
| 知识库 | `core/knowledge_base.py` | 业务规则+老师傅经验 | 接向量数据库，做RAG |
| 人审闸门 | `core/human_review.py` | 高风险动作审批 | 接飞书/企业微信审批流 |
| 审计日志 | `core/audit_log.py` | 全链路留痕可追溯 | 对接SIEM/日志平台，持久化到数据库 |

## 项目一：小型工厂降本增效AI助手（30人级 · 3个月）

### 适用对象
30人左右小型制造厂，已有ERP/财务软件，数据在系统里但靠人找、靠人对。

### 第一步：现场调研（第1-2周）

**必须到场做的事：**
- [ ] 跟财务跑2天：看对账全流程，记录对什么、对几次、哪里最耗时
- [ ] 跟销售跑1天：看客户问交期时，销售问了哪些人、打了几个电话
- [ ] 跟老板/厂长聊：他每天早上最关心哪3个数字
- [ ] 确认现有系统：ERP是用友T+/金蝶KIS/管家婆？有没有数据库直连权限？

**交付：** 一页纸现状流程图 + 痛点排序

### 第二步：数据接入（第3-6周）

**必须接的数据：**
| 系统 | 要取的数据 | 接入方式 | 优先级 |
|------|-----------|---------|--------|
| ERP | 采购订单、收货单、应付发票 | 数据库直连/API导出 | P0 |
| ERP | 销售订单、库存余额 | 同上 | P0 |
| ERP/WMS | 出入库流水 | 数据库视图 | P1 |
| MES（如有） | 工单完工进度 | API | P1 |

**验收标准：** Agent能从ERP取到近3个月完整数据，不缺表不断档。

### 第三步：跑通3个场景（第7-10周）

**场景1：采购三单匹配对账**
- 输入：采购订单 + 收货记录 + 发票
- 自动核对：数量一致性、金额差异>1%标记、未匹配项清单
- 人工确认：付款动作仍由财务审核
- **验收指标：** 对账工时从5人天/月降到1人天/月，差异检出率>95%

**场景2：销售交期答复**
- 输入：订单 + 库存 + 在制 + 排产
- 自动输出：可交日期 + 风险提示
- 人工确认：对客户承诺前销售复核
- **验收指标：** 交期答复从"来回问3天"到"5分钟出建议"，答复准确率>90%

**场景3：老板每日一页**
- 自动汇总：生产进度、质量异常、库存预警、待办事项
- 按影响程度排序，一页纸展示
- **验收指标：** 老板每天花<5分钟看，替代原来"逐个部门问"

### 第四步：上线推广（第11-12周）
- [ ] 培训财务/销售/厂长各1人，会用会查
- [ ] 跑2周，收集问题，修正规则
- [ ] 正式上线，明确"AI建议+人确认"的工作方式

### 人审边界（硬规则）
| Agent可以做 | 必须人审 |
|------------|---------|
| 自动核对数据、输出差异清单 | 确认付款、对外承诺交期 |
| 汇总异常、生成日报 | 对客户回复交期 |
| 提示风险 | 重大决策 |

## 项目二：中型制造企业智能生产协同Agent（200人级 · 6个月）

### 适用对象
200人制造企业，ERP/MES/WMS/QMS均已上线，数据孤岛，需要跨部门协同。

### 第一步：组织对齐（第1-4周）

**关键动作：**
- [ ] 找到"执行一号位"（通常是生产副总/厂长），他必须愿意推
- [ ] 三方对齐：老板要什么 / 中层怕什么 / 一线烦什么
- [ ] 选试点部门：先锁定生产部，不要全厂铺开
- [ ] 化解"替代焦虑"：明确Agent是助手不是替代，老师傅经验是知识库来源不是被替代对象

**交付：** 试点部门、目标、成功标准的书面确认

### 第二步：系统接入与知识萃取（第5-12周）

**必须接的系统（对应图5全景图）：**
| 系统 | 数据范围 | 接入方式 |
|------|---------|---------|
| ERP | 订单/库存/BOM/采购 | 数据库/API |
| MES | 工单/报工/批次/产线 | 数据库/API |
| WMS | 出入库/库位/批次 | API |
| QMS | 检验记录/不良品/追溯 | 数据库 |
| SCADA | 设备状态/报警/运行时长 | OPC UA/MQTT |

**知识萃取（关键，别跳过）：**
- [ ] 跟3-5个老师傅各访谈2次，把维修经验、判断诀窍录下来
- [ ] 把质量判定标准、异常处理SOP结构化进知识库
- [ ] 把设备点检标准、保养周期表录入系统

### 第三步：三个生产场景上线（第13-24周）

**场景4：生产齐套与欠料预警**
- 自动计算：需求 = BOM用量 × 工单数量；可用 = 库存 + 在途 - 已分配
- 输出：缺料清单 + 影响工单 + 催料建议
- **验收指标：** 缺料导致停线时间减少30%

**场景5：设备点检与维保建议**
- 自动汇总：今日报警 + 超期保养 + 重复故障
- 调用知识库：给出维修建议（像老师傅在场）
- **验收指标：** 非计划停机减少20%，点检漏检率降为0

**场景6：质量批次追溯与归因**
- 输入：问题批次号
- 自动拉通：原料→工序→设备→人员→检验→出库全链
- 关联：同期同设备产品、同原料批次
- **验收指标：** 客诉追溯时间从3天缩短到4小时，根因定位准确率>80%

### 人审边界
| Agent可以做 | 必须人审 |
|------------|---------|
| 计算缺料、输出预警清单 | 改排产、停线 |
| 汇总报警、给维修建议 | 停机检修方案 |
| 追溯批次、列可能原因 | 召回决定、质量判责 |

## 项目三：大型制造集团AI治理与智能体平台（12个月）

### 适用对象
大型国企/制造集团，多工厂多产线，安全合规审计要求高。

### 建设内容

**1. 治理型AI基础设施（第1-6个月）**
- [ ] 数据安全分级：按业务域划分敏感等级，敏感字段脱敏
- [ ] 权限隔离：按工厂/部门/岗位细粒度授权，最小权限原则
- [ ] 审计追溯：Agent所有取数/操作/决策全链路日志，可回放
- [ ] 人机协同评测：AI输出准确率监控、人工抽检、效果看板

**2. 企业级业务蓝图（第3-6个月）**
- [ ] 跨部门流程梳理：从订单到交付全价值链
- [ ] 业务能力地图：标注每个环节的数据、规则、AI切入点
- [ ] 审批节点设计：哪些步骤AI做、哪些必须人审

**3. 智能体平台（第6-12个月）**
- [ ] 统一Agent编排引擎：多Agent协同、工作流设计器
- [ ] 模型管理：通用大模型+行业模型调度，成本控制
- [ ] 知识库平台：支持多工厂知识隔离与共享

### 验收指标
- 集团级数据打通率>80%
- 所有AI操作100%可审计回放
- 满足等保/国资监管要求
- 至少10个场景上线运行

## 项目四：设备预测性维护AI Agent（4个月）

### 聚焦设备维保专项，独立可交付

### 数据接入清单
| 数据 | 来源 | 用途 |
|------|------|------|
| 设备运行参数（温度/振动/电流） | SCADA/IoT传感器 | 异常检测 |
| 报警历史 | 设备系统/SCADA | 故障模式库 |
| 维修工单 | EAM/工单系统 | 根因关联 |
| 点检记录 | 点检系统/纸质电子化 | 趋势分析 |
| 保养周期 | 设备台账 | 超期提醒 |
| 维修经验 | 老师傅访谈 | 知识库 |

### 实施步骤
1. 选3-5台关键瓶颈设备（停线损失最大的）
2. 接SCADA数据，跑通数据采集
3. 建故障特征库：先从报警规则入手，再逐步加ML预测
4. 做点检助手：每日自动生成点检清单+异常提醒
5. 4个月后评估：非计划停机时间是否下降

### 验收指标
- 关键设备非计划停机减少25%
- 点检效率提升40%
- 维修建议采纳率>70%

## 项目五：质量全链路追溯与根因分析AI（6个月）

### 数据接入清单
| 数据 | 来源 | 用途 |
|------|------|------|
| 检验记录（首检/巡检/末检） | QMS | 不合格判定 |
| 批次生产记录 | MES | 正向/反向追溯 |
| 设备工艺参数 | SCADA/PLC | 根因关联 |
| 原料批次与供应商 | ERP/WMS | 供应商追溯 |
| 操作人员与班次 | MES/HR | 人员关联 |
| 不良品记录与返工记录 | QMS | 不良分布分析 |

### 实施步骤
1. 以批次号为主线，打通QMS+MES+WMS
2. 实现正反向追溯：给批次号，30秒内出全链图谱
3. 做根因分析：不合格自动关联设备参数/人员/班次/原料
4. 做质量日报：每日自动汇总不良TOP问题
5. 逐步从"事后追溯"走向"事前预警"

### 验收指标
- 客诉追溯时间从3天→4小时
- 根因定位准确率>80%
- 质量月报自动生成，节省质量工程师2人天/月

## 通用落地检查清单（每个项目必做）

### 数据准备
- [ ] 物料编码是否统一？（不统一先治理，否则AI算不准）
- [ ] BOM是否准确？（BOM错了，齐套计算全错）
- [ ] 主数据（供应商/客户/物料）是否完整？
- [ ] 历史数据有没有6个月以上？（没有就先采集积累）

### 组织准备
- [ ] 有没有"执行一号位"？（没有=项目推不动）
- [ ] 一线员工会不会抵触？（要提前沟通：AI是助手不是替代）
- [ ] 谁来维护知识库？（没有专人维护，3个月后知识库就过时了）

### 技术准备
- [ ] 现有系统有没有API或数据库直连权限？
- [ ] 数据安全要求？（数据能不能出厂？要不要私有化部署？）
- [ ] 网络环境能不能支撑？（SCADA数据实时性要求高）

### 上线前
- [ ] 高风险动作是否全部配置了人审？
- [ ] 审计日志是否完整？
- [ ] 有没有2周试运行期？
- [ ] 出了问题谁负责？（要明确运维责任人）

## 6级成熟度路线（对照图6）

| 级别 | 状态 | 企业占比 | 本项目支持到哪 |
|------|------|---------|--------------|
| Level 1 | 手工台账，人找数 | 30% | 数据层已打通 |
| Level 2 | 系统看板，数在系统里 | 30% | 已实现 |
| Level 3 | 单场景Agent解决高频问题 | 25% | **当前MVP达到此级** |
| Level 4 | 多场景Agent串起来 | 10% | 扩展后可达 |
| Level 5 | 岗位AI同事独立完成一类任务 | 4% | 需长期运营 |

**大多数企业从Level 3开始最现实。**
